# ⚖️ 訴訟當事人 AI 產製內容互動專案（AI 訴訟意見雙軌分流工作流系統）

> **專案版本**：v2.0（模組化 Agent 決策引擎版）  
> **適用領域**：民事訴訟、民事強制執行、勞動事件、家事事件、法扶指派案件及各類訴訟代理實務

## 🎯 專案緣起與核心痛點

隨著生成式 AI（如 ChatGPT、Claude 等）普及，訴訟當事人經常使用 AI 產製大量空泛意見、法理拼貼或未經查證之書狀草稿，甚至要求律師依其 AI 內容撰寫書狀。此類內容常隱含：
1. **缺乏客觀具體事實**，流於空洞抽象法條拼湊。
2. **抓小放大**，模糊訴訟主戰場。
3. **舉證責任錯置**，盲目要求對方舉證。
4. **致命不利自認（自爆地雷）**，不慎承認收受款項、簽名真正、侵權接觸或拋棄時效利益。

本專案旨在建立一套**標準化、高防禦性且兼顧當事人心理需求之雙軌工作流系統**。

---

## 🛡️ 三大核心戰略目的

1. **維護律師專業代理品質與法庭信譽**：  
   確保律師具名之正式書狀（準備書狀、答辯狀）聚焦於核心事實與嚴謹攻防，不被當事人 AI 雜訊稀釋。
2. **劃定專業服務邊界與節省溝通成本**：  
   明確宣示「訴訟代理不包含法律補習與教學」，將當事人精力導引至「具體事實與證據查核」。
3. **宣洩當事人主張慾望並達成風險切割**：  
   當事人堅持提出之補充意見，格式化為《民事陳報個人意見狀》，由當事人**「個人名義具狀簽章」**，責任自負，律師不背書。

## 🔄 雙軌分流核心工作流架構

`mermaid
flowchart TD
    Start[當事人傳送補充意見 / 書狀草稿] --> Ingest[Phase 1：接收素材與 B 點診斷]
    
    Ingest --> B{【B點判定】<br/>是否含客觀具體事實或新證據？}
    
    B -->|【有實益】<br/>具體人事時地物/單據線索| FactExtract[【軌道一：律師專業攻防軌】<br/>1. 提煉事實與待證清單<br/>2. 納入《準備書狀/答辯狀》<br/>3. 由訴訟代理人具狀簽章]
    
    B -->|【無實益】<br/>純法理拼貼/空泛推論/枝節爭執| Phase2[Phase 2：啟動審慎溝通與事實導引]
    
    Phase2 --> SendComm[發送三大標準板塊話術：<br/>一、關鍵證據評估與訴訟風險說明<br/>二、律師建議之訴訟方向<br/>三、對造書狀與證據核對 7 大問卷]
    
    SendComm --> G{【G點判定】<br/>當事人後續態度？}
    
    G -->|回歸理性配合提供事實| FactExtract
    G -->|堅持將全部意見送交法院| Phase3[Phase 3：啟動當事人個人陳報軌]
    
    Phase3 --> MineScan[1. 執行 6 大不利自認地雷掃描]
    MineScan --> CheckMine{是否含致命自認？}
    
    CheckMine -->|有自認風險| Warn[提示法律風險]
    CheckMine -->|無自認 / 當事人堅持提出| GenPleading[2. 產製《民事陳報個人意見狀》<br/>（原汁原味整併當事人全部意見）]
    Warn --> GenPleading
    
    GenPleading --> FinalSign[3. 交由當事人「個人具名簽章」<br/>（律師不列名、不背書）向法院陳報]
`

## 🛠️ 免安裝網頁版產狀工具

本專案附帶之 **民事陳報個人意見狀產製工具.html**（亦作為 GitHub Pages 入口 index.html）：
- **純本地端運行**：無須安裝任何軟體或 Python 環境，不將任何案情資料上傳伺服器，100% 保障個資安全。
- **不利自認即時提示**：輸入時自動偵測收受款項、承認簽名等關鍵詞並跳出風險提醒。
- **一鍵下載標準 Word**：自動完成 20pt 置中標題、14pt 標楷體、1.5 倍行高、標準層次縮排之法院書狀排版。
